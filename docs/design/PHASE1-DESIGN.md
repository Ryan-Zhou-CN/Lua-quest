## 0. 方向决策记录

第一阶段比对了 5 个候选方向（卡牌自走棋 / 工作室经营 / 可编程法术地牢 / 剧本叙事 RPG / 像素乐园），Hermes 与 OpenCode 独立设计后在工作经营与法术两个方向上收敛。

**最终拍板**：保留「工作室模拟经营」框架，但核心玩法是**真实工程体验** —— 经营是外壳，贴近 Roblox 实际开发的工作过程才是游戏本体（用户原话：「要贴近 Roblox 实际，工作室可以保留，我想让它更工程风格」）。

**贯穿一切的设计公理**：

> 永久删除 `code.includes()` 式字符串匹配判定。玩家代码必须产生**可见后果**（QA 报告、机器人行为、性能数据）——「世界回应代码」是玩着学和做题的分水岭。

## 1. 核心体验定义

### 1.1 工作区布局（仿 Roblox Studio 五面板）

```
┌─────────────────────────────────────────────────────────────────────────┐
│ 顶部工具栏：运行/测试/提审 | 当前委托 | 资源栏(钱/声望/技术债)              │
├───────────┬───────────────────────────────────┬─────────────────────────┤
│ Explorer  │       脚本编辑器（多标签）          │  Properties             │
│ 实例树     │                                   │  选中实例的属性/事件/方法 │
│ Workspace │  ┌─────────────────────────────┐  │                         │
│ Replicated│  │ Output (print 流式)          │  │                         │
│ Storage…  │  ├─────────────────────────────┤  │                         │
│           │  │ Console (warn/error)        │  │                         │
│ 右键新建  │  ├─────────────────────────────┤  │                         │
│ Script/   │  │ Test Runner (验收用例绿/红)  │  │                         │
│ Module…   │  ├─────────────────────────────┤  │                         │
│           │  │ QA Report (机器人回放报告)    │  │                         │
└───────────┴──┴─────────────────────────────┴──┴─────────────────────────┘
```

交互要点：
- Explorer 选中 → Properties 联动刷新；双击脚本 → 编辑器开新标签
- Output 实时流式追加、按级别过滤；Test Runner 用例可点击跳转代码行
- QA 面板只读，展示提审后的机器人回放报告

### 1.2 委托周期（分钟级体验）

| 阶段 | 时长 | 玩家动作 | 系统反馈 |
|------|------|----------|----------|
| 接单 | 30s | 委托大厅挑卡 → 接单 | 自动生成工程骨架，打开 `Main.server.lua`，底部切到「需求文档」Tab |
| 开发 | 5-15min | 写 Luau → Ctrl+Enter 自测 → 看 Output 修 bug → 拆 ModuleScript | 实时指令数/执行时间；lint 波浪线；（P1）类型检查提示 |
| 自测 | 1-3min | 「运行测试套件」 | 用例逐条绿/红；性能面板帧时间/内存/指令数 |
| 提审 | 10s | 「提交 QA」 | 委托进入「QA 中」列，倒计时 |
| QA 报告 | 30s | 读报告 | 结构化：复现步骤 → 期望/实际 → 堆栈 → 性能 → 严重等级 |
| 返工/发布 | — | 返工：技术债+5 继续；发布：按质量/性能/功能结算 | 解锁新委托/技能点/荣誉 |

## 2. 委托系统

### 2.1 委托卡结构（真实需求文档风格）

每张委托卡包含：

- `background`：像真需求文档的背景（「美术已把怪物模型放 ReplicatedStorage.Monsters…」）
- `acceptanceCriteria[]`：AC-1…AC-N，标 P0/P1 优先级 —— **这就是隐藏测试用例的来源**
- `nonFunctionalRequirements[]`：性能预算（指令数/内存）、质量（lint 零错误）、架构（模块化要求）
- `budget`：金钱/工期/声望
- `requiredSkills` / `unlocks`：技能树联动
- `template`：预置工程骨架
- `qaConfig`：机器人数量/时长/场景（normal、high_latency、player_leave_mid_wave…）

## 3. 模拟 Roblox 运行时（QA 引擎）

### 3.1 API 模拟分级

| API 类别 | L0（P0） | L1（P1） | L2（P2+） |
|---------|----------|----------|-----------|
| Instance 树 | Instance.new、Parent、FindFirstChild、GetChildren、Destroy | 全属性、Clone、IsA、WaitForChild、SetAttribute | 完整生命周期、AncestryChanged、序列化 |
| 属性/事件 | 基础读写、Changed、Touched、ClickDetector | BindableEvent/Function、RemoteEvent/Function | 网络所有权、并发顺序 |
| RemoteEvent | FireServer/Client、基础序列化 | 限流、中间件、压缩 | 带宽/丢包/乱序模拟 |
| DataStore | GetAsync/SetAsync/UpdateAsync、退避重试 | OrderedDataStore、缓存层、版本冲突 | 事务、跨服一致性 |
| 物理简模 | 无 | 重力/碰撞组、Raycast、CFrame 数学 | 完整约束求解器 |
| CollectionService | AddTag、GetTagged | 标签生命周期、批量操作 | 复制与同步 |

### 3.2 机器人玩家 → Bug 触发 → QA 报告

- **行为模型**：行为树（战斗/卡住跳出/低血找掩体/拾取/游荡），seeded 确定性
- **注入式 Bug 触发**：空指针（FindFirstChild 无保护）、竞态（双机器人同杀一怪写同一 Key）、内存泄漏（连接未 Disconnect）、性能尖峰（第 10 波 50+ 怪同帧生成）、安全漏洞（客户端假参数未校验）、状态机死锁（快速切换攻防）
- **QA 报告**：报告 ID/种子/机器人配置/判定(FAIL)/逐条 finding（标题/类型/严重级/复现步骤/堆栈/指标/修复建议）/性能汇总/通过与失败的 AC 清单

### 3.3 【工程关键】虚拟时钟

机器人与 task 调度跑在**虚拟时间**里：同一种子 → 同样行为 → bug 可复现、可回放、可分享。这是整个 QA 引擎的地基，P1 必须实现。

## 5. Luau 断层：现状与策略 ⚠️

### 5.1 现状确认（OpenCode 代码库核实，修正 Hermes 初稿）

> ❗ Hermes 初稿假设存在 `lua-engine.js` 的 `luauToLua()` 正则转译层 —— **该文件不存在**。
> 实际现状：`fengari-wrapper.js` 直接执行 Lua 5.3，**没有任何转译层**。
> 后果：Luau 类型注解、`+=`、`continue` 会**直接语法报错**，断层比预想更大。

### 5.2 三条路线

| 路线 | 思路 | 成本 | 教学真实性 | 调试体验 |
|------|------|------|-----------|----------|
| A. 转译层 | Luau→Lua 5.3 转译（先词法级、后 AST 级）+ Source Map | 中 | 高 | 转译后行号需映射 |
| B. 共同子集 | 只教 Lua∩Luau 交集，文档标注差异 | 零 | **低（违背工程风格定位）** | 完美 |
| C. Luau WASM | 换官方 Luau VM 的 WASM 构建 | 高（1-2MB、沙箱重写） | **最高** | 原生 |

### 5.3 已拍板路线：直接上 Luau WASM（方案 C）✅

**决策记录（2026-10-03，用户拍板）**：不做转译层、不教阉割子集，P0 直接切换 Luau WASM VM，追求 100% 教学真实性与真类型检查。

**候选实现（OpenCode 技术调研，2026-10-03）**：

| 选项 | 来源 | 优势 | 风险 |
|------|------|------|------|
| **C1: `luau-web` npm 包**（首选） | xNasuni，v1.4.0，MIT | 现成 Luau WASM + **动态 JS 互操作**（桥接模拟 Roblox API 的关键）、有沙箱安全文档 | 社区维护、指令计数能力待验证 |
| C2: 自编译官方 Luau | luau-lang/luau + Emscripten（参考官方 playground） | 完全可控、可定制中断回调 | 需维护 WASM 构建链 |
| C3: `ulua`（纯 Rust Luau→WASM） | rust 社区，含类型检查器 | 无 C 工具链 | 项目太年轻（2026 新作） |

**P0 第一个任务 = 技术验证 Spike（1-3 天），Go/No-Go 清单**：

1. `luau-web` 在浏览器跑通基本 Luau 代码（含类型注解、`+=`、`continue`）✅ 才算 Go
2. 动态互操作：JS 函数注入 Luau 全局（模拟 `Instance.new`）双向调用
3. **指令预算**：验证 VM 中断回调可统计指令数并软中断（性能系统的地基）
4. 内存限制与死循环保护（`while true do end` 必须能被掐断）
5. 错误堆栈带行号、可捕获到 JS 侧
6. 体积 ≤ 2MB（gzip 后）
7. `luau-analyze` WASM 类型检查可行性（官方 playground 已证明，确认能否独立抽取）

**Spike 失败的降级预案**：回退方案 A（词法级转译层），设计文档第 5.2 节路线表保持有效。

在经营成长/作品集/粉丝反馈之外，新增工程荣誉（部分）：

- **性能**：60FPS 守护者（连续 3 委托帧时间<16.6ms）、内存极客（无泄漏+峰值<10MB）、指令预算内（10 次运行零超限 → 预算永久+50k）

- **梗**：print 调试大师（单次>50 次 print → 彩虹 print 皮肤）、复制粘贴工程师（重复率≥30% → 解锁重构建议）
